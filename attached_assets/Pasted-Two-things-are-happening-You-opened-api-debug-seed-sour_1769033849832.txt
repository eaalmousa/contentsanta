Two things are happening:

You opened /api/debug/seed-sources in the browser → that is a GET request.
But your endpoint is POST (as designed). A GET will miss the route and fall through to the SPA, which then shows its own 404.

Even worse: your server is currently allowing SPA fallback to catch /api/... routes when the API route isn’t matched. That’s why you see the React 404 page instead of a JSON 404/405.

Do this now (the correct POST call)

Open DevTools → Console and run exactly:

fetch("/api/debug/seed-sources", {
  method: "POST",
  credentials: "include",
  headers: { "Content-Type": "application/json" },
})
  .then(async (r) => ({ status: r.status, body: await r.text() }))
  .then(console.log)
  .catch(console.error);

What you should see

status: 200

body like: {"success":true,"inserted":41,"skipped":0}

If you see HTML in body

Then the server is still serving the SPA for that path (route not mounted OR fallback order is wrong). That’s a backend routing bug, not a data bug.

The real fix you must implement in Replit (so this never happens again)
Fix A — API must never fall into SPA fallback

In your Express server, the order must be:

mount API routes

if route starts with /api/ and wasn’t handled → return JSON 404

only then do SPA fallback (index.html) for non-API routes

Add this after app.use("/api", apiRouter) and before app.get("*", serveIndex):

app.all("/api/*", (req, res) => {
  return res.status(404).json({ message: "API route not found", path: req.path });
});


Now /api/debug/seed-sources will return JSON even if missing, instead of showing the React 404 page.

Fix B — If seed-sources is POST-only, add a GET that returns 405 JSON

So opening it in a browser is self-explanatory:

router.get("/debug/seed-sources", (req, res) => {
  return res.status(405).json({ message: "Use POST /api/debug/seed-sources" });
});
