Publishing targets (the 400 fix)

The “default workspace fallback” is fine, but you should also do one of these:

Preferred: Frontend always includes workspaceId from the session/current workspace state.

Fallback: Backend derives workspaceId from authenticated user (e.g., “default workspace for user”) consistently in all publishing endpoints, not just GET.

Also: 400 is the wrong status for “missing workspaceId” in many setups. If the server can derive it, don’t 400. If it truly can’t, return a 400 with a clear message and errorCode: "WORKSPACE_REQUIRED".
