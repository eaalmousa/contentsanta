B) TOPIC-LEVEL REAL ESTATE FILTERING
--------------------------------------------------

Problem:
The global Inbox now shows general business stories (Mitsubishi gas deal, Nestlé infant formula recall, etc.) from Gulf Business. That is fine for the global feed, but the user’s Real Estate topic should primarily pick **property-related** stories.

We already pass `topicQuery` to `runTopicDiscovery`. Now we need a stricter relevance filter.

Requirements:

1) In the topic discovery pipeline (where we select source items for a topic), implement a relevance scoring function that uses:
   - the topic’s `topicQuery` text
   - a small built-in vocabulary of real-estate related terms, e.g.:
     - "real estate", "property", "housing", "homes", "mortgage", "rent", "rental", "leasing", "tenants"
     - "residential", "commercial real estate", "office space", "warehouse", "industrial park"
     - "construction", "development", "masterplan", "land department", "land plot", "freehold"
   - and the item’s title + summary.

2) Use this function to compute a `topicRelevanceScore` per item. Then:
   - discard or strongly down-rank items with very low score (e.g., no match to either the topicQuery OR the real-estate vocabulary).
   - prioritize items with strong matches to titles like "housing", "property", "real estate", "mortgage", "home loan", "villa", "apartment", "realty", etc.

3) The global Inbox can still show all items, but:
   - For topics like “GCC Real Estate & Property News”, the Smart Editor / per-topic story list should only include items above a relevance threshold.
   - Add logging so that for a test run we can see how many items were rejected vs accepted based on relevance.
