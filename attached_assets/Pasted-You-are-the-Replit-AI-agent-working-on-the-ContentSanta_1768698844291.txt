PART 1 — Add Google News RSS support to the RSS ingestion pipeline
1. Detect Google News feeds

In the backend RSS fetcher/parsing layer (where we currently read a feed.url and parse RSS XML):

Detect if feed.url contains "news.google.com/rss".

When it does, route to a specialized Google News parser; otherwise, use the existing generic RSS parser.

2. Implement parseGoogleNewsRssItem

Create a helper (or extend existing parser) that:

For each RSS <item> from Google News, extracts:

title

link (the Google News redirect URL)

pubDate / ISO date

description / content:encoded

<source> name (if available)

Then use the same logic I used in n8n to extract the real article URL from the HTML content:

// Pseudocode / TypeScript-style
function extractCanonicalUrlFromGoogleNews(contentHtml: string, fallbackLink: string): string {
  if (!contentHtml) return fallbackLink;
  const match = contentHtml.match(/href="([^"]*)"/);
  if (match && match[1]) return match[1];
  return fallbackLink;
}


Map into our internal “source item” shape. For each parsed item, set at least:

title

url → canonical article URL from the regex above

originalLink (optional) → Google News link (for debugging)

summary / contentSnippet → from description/content

publishedAt

publisherName → value from <source> if present

3. Geo + language tagging from the feed URL

When parsing a Google News feed, derive geo + language from the feed URL parameters and persist them in the item:

Parse gl= and ceid= query params from the feed URL, e.g.:

gl=AE, ceid=AE:en → country = "AE", language = "en"

gl=SA, ceid=SA:ar → country = "SA", language = "ar"

Store country and language on the source item (or story) in the same way we store them for other feeds.

Also tag: sourceType = "google_news" (or similar) on the item so we can debug later if needed.

Important: Do not change the DB schema unless needed. If we already have fields for country and language on items/stories, reuse them.
